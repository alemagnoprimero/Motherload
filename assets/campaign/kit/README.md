# Art kit

Shared helpers for the art programme's generators (built in art item A4). Every art session that draws with code imports these instead of writing its own. Authoring only: the game loads the rasterized PNGs, never these modules.

| Module | Use it for |
|---|---|
| `random.mjs` | `random(seed)` and `fork(name)`: seeded streams that give the same numbers on every machine |
| `palette.mjs` | `band(id)` (the A1 swatch cards), `board(key)` (the board samples for sky, props and emitters), Lab and LCh moves (`withL`, `shiftL`, `mixLab`, `tiers`), `bevelColours` |
| `svg.mjs` | `num`, `polygon`, `layer`, gradients (a stop may carry an opacity, `[offset, colour, opacity]`, so a glow fades to transparent), `svgDocument`, the outline rule (`outlineWidth`, `outlineStroke`), `periodic` for tiling pages, `bevelEdges` |
| `emissive.mjs` | `emissivePair`: the base frame and its `-emissive` sibling from one description (the game draws the sibling ADD above the darkness: "Emissive siblings at runtime" below) |
| `records.mjs` | `upsertFrames` into a `frames.json`; `writeProvenance` for `assets/campaign/source/provenance/<asset>.json` |
| `review.mjs` | Panels at the board's tile scale and their rasterizing (resvg, as the game's assets), for `scripts/art-review.py` |

A session's round, in order:

1. Draw with the kit; keep numbers through `num` so sources rebuild byte-identically.
2. Write a small driver like `scripts/art-review-a4.mjs` that composes candidate panels at the board's tile scale, then run `python3 scripts/art-review.py <out>/review.json <out>/sheet.png` for the sheet, the measures and the IoU duplicate check (`scripts/art-review-a12.mjs` and `.py` are the prop version: frames in band blocks, cross-variant IoU). `scripts/art_tiers.py` counts shading tiers per material zone, from `data-zone` groups in the SVG or from zone masks on a render.
3. After the director's pick, rebuild everything from source with `PYTHON=python3 npm run assets:rebuild` (both worlds' sources and assets, then the band pages). Builds are byte-identical on every machine (audit T13b): resvg renders the SVGs without a browser and `scripts/png-canonical.mjs` writes every PNG the same way, so only images whose pixels changed show up as modified, and CI's `verify` job rebuilds and fails on any difference. `python3 scripts/art-unchanged-pngs.py` stays as a diagnostic (it tells a pixel change from an encoding change); a rebuild no longer needs its `--restore`.
4. Capture the fixture with `scripts/art-captures.mjs`; add the capture folder to `review.json` under `frames` to measure it beside the board.
5. Write the provenance record with `records.mjs` and update the asset tracker's rows.

Palette rule: the swatch cards and board samples are on-screen targets within 3 L\*, not shader inputs (style guide §1).

## Emissive siblings at runtime

Audit T13b (a). The convention every lit prop follows; the survey beacon's lamp (`mission-beacon-emissive`) is the first, and A13's rig headlamp and cabin indicator (`rig-cabin-emissive`) the second.

**Authoring.** Describe the frame once with `emissivePair({ name, width, height, layers })`. A layer that lights up is `{ name, unlit, lit }`: `unlit` is how it looks with the power off (it goes in the base frame), `lit` only the light (it goes in `<name>-emissive`, on transparent). Save both frames with the same size; frames.json lists both. Draw the lit part without the outline, just inside the base's outline (the beacon's glass: the base circle is r 8 with a 3-unit stroke, the lit circle r 6.5 with none), so the light never paints over the ink. Choose the colours so that off + lit = the colour the lit part should read where nothing darkens it: the game adds the sibling's RGB to the frame, so the beacon's lit glass is `#f6e1af` − off glass `#4b4336` = `#ab9e79`, and in full light the beacon looks exactly as the old single frame did. A halo may reach outside the base's silhouette, but keep it inside the frame and small: on a base without the wreck mask (the rig) it lights whatever is beside the prop, unknown rock included (§9.2 allows unknown rock to lift by at most 2 L\*). No glow is baked into the base, and nothing time-varying belongs in either frame. Flicker, if a prop ever needs it, goes on the scene clock and stays static under reduced motion (§9.3).

**Packing.** Nothing to do. `scripts/campaign-zones.mjs` gives the sibling its base's zone, page set and hero status (`zone(emissiveOf(name) ?? name)`), and `scripts/pack-campaign-atlas.py` keeps it on its base's page at every density, @4x included for the hero set: a group takes one page whenever one 2048 × 1024 page holds it, and a group that spills onto more pages is packed with each base and its siblings as one unit that never straddles a page break (the packer proves that path on a synthetic group before each run, and stops if a sibling still lands away from its base). `check-campaign-assets.mjs` fails the build unless the sibling has a base of the same size in the same world, on the same page at every density, with the same source size and pivot in the page JSON (the runtime registers the trimmed sibling by copying its base's scale and origin). The world build skips the sibling's DOM icon and draws the base's icon lit (no darkness in the DOM). The sibling usually fits in the page's free space: the beacon's lamp changed no page size, so it costs 0 resident bytes.

**Drawing** (`src/campaign/render/emissive.ts`, called from `scene.ts`). After `image()` draws a base frame and snaps it to device pixels, it queues the base; once the frame's last sprite is drawn (after the rig), the pass draws every queued base's sibling from the base's final state: the same texture page, position, origin, scale (and so display size), flip, rotation, alpha, and the base's mask. The siblings come from their own pool, never from the scene's base sprites (which never reset their blend mode), and draw with the ADD blend: WebGL `ONE, DST_ALPHA` on premultiplied textures over the opaque frame, Canvas `lighter`. Transparent texels add nothing; alpha scales what is added; tint is not used (Canvas ignores it).

**Depth.** Above the darkness (the light map is at 17):

| base depth | sibling depth | why |
|---|---|---|
| below 18 (terrain 10, ore 13, scenery 14, markers 15, hazards 16, shelves 17) | 17.6 | one band for every scenery and prop sibling, just above T1-lite's ADD core (17.5), so they share its ADD run |
| 18 to 23.6 (thrust 18, rig layers 20–23.6, `src/campaign/render/rig-layers.json`) | 23.9 | one band for every rig sibling, above every rig layer and below the effects (24): the rig's lit parts make one ADD run and add over whatever rig layer lies under them, as the A13 review composites them (`docs/qa/a13-rig-shading`, sheet-emissive), so keep a rig lamp where no rig layer covers it in any pose |
| 24 and up | the base's depth + 0.05 | just above its own base |

A scenery sibling sits above every scenery sprite, so a hazard (16) or shelf (17) drawn over its base does not cover its light: keep lit parts where no other scenery overlaps them.

**Hidden information.** A sibling is drawn only when its base was drawn this frame, so it never shows anything its base would not. A base under the wreck mask (known cells only: wrecks, POI markers) passes the mask on, except when every cell under the sibling's drawn box is known: there the mask would pass every pixel anyway, so the sibling skips the stencil pass and joins the ADD run. `docs/qa/t13b-asset-pipeline/emissive-runtime.mjs` checks that an unknown cell under the beacon's lamp is pixel-identical with and without the pass on both renderers; the fog check and `render-acceptance.mjs`'s hidden-geology crops run as before.

**Budget.** WebGL draws with the beacon on screen (desktop and phone): 6 with the bases alone, 6 with the lamp lit (+0, it joins T1-lite's ADD run), 8 when the lamp must keep the wreck mask (+2: the stencil pass and the masked run). The limits are 12 desktop and 10 phone. Every separate ADD run costs about 2 draws (into ADD and back), so the rig siblings share one depth (23.9, after the last rig layer) instead of interleaving with the NORMAL rig layers, where each run would cost 2 more. Measure with `emissive-runtime.mjs` (which also gives the `?debug=no-emissive` comparison) and `npm run test:render`.

**Debug.** `?debug=no-emissive` draws the bases alone (`renderDebugOptions`), for before/after captures; nothing changes without it. `window.__campaignDebug.emissives()` lists the siblings drawn this frame with the base each copied (frame, page, position, size, flip, rotation, alpha, depth, blend mode, mask), and `data-emissive-sprites` counts them.

## Adding a rig frame at @4x, with its sibling

Audit T13b (b, c). What A13 (item 3) and any later rig or hero-prop work does; nothing in the packer, the manifests or the game needs editing by hand.

1. **Draw** the frame in `assets/campaign/source/create-w01-sources.mjs` (W02's level-2 parts, `rig-*-2`, `rig-drill-collar-*-2` and `tool-*`, in `assets/campaign/w02/create-sources.mjs`) on the shared 128 × 128 rig canvas: pivot (64, 64), tread baseline at y 100. Keep the track's outer edge exactly on y 100 (A13's `rigBody()` in `assets/campaign/source/w01-rig.mjs` draws the outline as a filled ring from y 72 to `TREAD_BOTTOM` = 100), so the tread meets the floor at every density; the check reads the lowest opaque row at @2x, @3x and @4x (100, 150 and 200 px).
2. **A lit part** (A13's headlamp and cabin indicator, `rigCabinFrames()` in `assets/campaign/source/w01-rig.mjs`) goes through `emissivePair`, which yields `rig-cabin` and `rig-cabin-emissive` from one description; the authoring rules are in "Emissive siblings at runtime" above. A W02-owned frame takes its sibling in W02's `frames.json`, because the game looks the sibling up in the base's own atlas.
3. **Names decide the rest.** Any `rig-*`, `tool-*` or `thrust-*` name is in the hero set and the `core` zone (`scripts/campaign-zones.mjs` `HERO`, `CORE`), so it is rendered from source at scale 1, 1.5 and 2 and packed on `campaign-w01-core-hero-{2,3,4}x-*` (W02: `campaign-w02-core-hero-*`); its sibling lands beside it at every density. A name outside those patterns stops the build with "no zone" until it is added to `campaign-zones.mjs`. A frame the game must always find goes in `REQUIRED_FRAMES` in `scripts/check-campaign-assets.mjs`.
4. **Rebuild** with `PYTHON=python3 npm run assets:rebuild`. A new generator or `upsertFrames` driver goes into that script after `create-w01-sources.mjs`, which rewrites `frames.json` whole. Commit every changed file under `assets/campaign`; CI rebuilds and fails on any difference, and its `rebuilt-campaign-assets` artifact holds the bytes it expected.
5. **Check** with `npm run assets:check` (zone pages, the tread baseline and pivots at every density, the sibling's same size, page, source size and pivot) and `npx vitest run tests/campaign-zones.test.mjs tests/campaign-emissive.test.mjs` (both iterate every frame and sibling, so new ones are covered).
6. **Budget.** W01's core hero page is 832 × 1024 at @4x (3.25 MiB) and the packer adds a second page when a group outgrows 2048 × 1024. The largest measured resident set with @4x hero pages is 58.43 MiB (desktop 1728 × 1117 @2, W01 row 18), against the 64 MiB desktop budget; rerun `docs/qa/t13b-asset-pipeline/zone-runtime.mjs resident` from a private copy after the art changes.
7. **Depth.** The game draws the rig as layers that share their position, one depth each, back to front: thrust 18, body 20, engine 21, energy 21.1, bay 21.2, cabin 22, hull 22.1, damage 22.5, feet 23, rack 23.1, `tool-thermal` 23.2, `tool-condenser` 23.3, `tool-preservation` 23.4, drill 23.5, collar 23.6. The table is `src/campaign/render/rig-layers.json`: `render/rig.ts` draws with it (`RIG_DEPTH`) and `scripts/art-review-a13.mjs` composites the review poses in its order, so the sheets show the stack the game draws. No two layers share a depth: Phaser 3.90 sorts the display list with a stable sort on depth, so equal depths keep the previous frame's order, which depends on how many sprites were drawn before (`docs/qa/t13b-asset-pipeline/captures/rig-layer-order.png`, before A13: the engine and the bay swapped between runs of the same tree). A new rig layer gets its own entry (a frame pattern and a depth between its neighbours, below 23.9); `tests/campaign-rig-layers.test.ts` fails on a frame with no layer or a shared depth. Every rig sibling draws at 23.9 (the table's `emissive`), above every rig layer, in one ADD run (about 2 WebGL draws).
